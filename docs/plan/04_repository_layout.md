Rationale for notable choices:

- **`uv`** manages the venv and lockfile (`uv sync --all-extras`). It is fast and deterministic; the
  lockfile is committed.
- **`httpx` sync client**, not async: the pipeline's concurrency is thread-based because Blender
  subprocess management and `filelock` are blocking; mixing in asyncio would add complexity for no
  throughput gain at our scale (≤ 4 concurrent Tripo tasks).
- **`pygltflib`** rather than `trimesh`: we only need accessor reads and embedded image bytes; `trimesh`
  pulls a large dependency tree.
- **`fake-bpy-module`** is stubs for type checking only. Runtime fakes used in tests are our own
  (`tests/fakes/fake_scene.py`).

## 3. Toolchain commands (`justfile` or `Makefile`, WP-00)

| Command | Does |
|---|---|
| `just setup` | `uv sync --all-extras && pre-commit install` |
| `just lint` | `ruff check . && ruff format --check . && lint-imports` |
| `just type` | `mypy src tests` |
| `just test` | `pytest -n auto -m "not blender and not tripo_live" --cov=tinyworld_pipeline --cov-branch --cov-report=term-missing --cov-report=json --cov-fail-under=80 && python tools/check_function_coverage.py` |
| `just test-blender` | `pytest -m blender` (requires `GP_BLENDER_EXE`) |
| `just fixtures` | `"$GP_BLENDER_EXE" -b --python tools/make_fixtures.py -- tests/fixtures/fbx` |
| `just ci` | lint + type + test |

## 4. CI (`.github/workflows/ci.yml`)

Jobs:

1. **lint-type-test** (ubuntu; macOS added when a runner is available): Python 3.12 and 3.13 matrix;
   `just ci`; uploads coverage XML; (Windows runners deferred — ADR-0002)
   fails if coverage < 80 % (line+branch; function coverage asserted by a small script over
   `coverage json` output since `coverage.py` has no built-in function threshold — WP-00 writes
   `tools/check_function_coverage.py`).
2. **blender-integration** (ubuntu): downloads Blender 4.5 LTS tarball (cached by version hash), sets
   `GP_BLENDER_EXE`, runs `pytest -m blender`. Required to pass on `main`, allowed to be skipped on
   draft PRs.
3. **unity-editmode** (optional, self-hosted or GameCI image): runs `unity/.../Tests/Editor`. Not a
   merge blocker in v1; documented as manual verification in `12_…`.

Secrets: none in CI. `tripo_live` tests are developer-only.

## 5. Versioning and compatibility

- Package version follows SemVer; `manifest.json` carries `schema_version` (int) and
  `pipeline_version` (string).
- Blender job protocol carries `protocol_version` (int). Orchestrator and Blender-side code ship
  together, so mismatches only occur if someone runs stale `entry.py`; the runner rejects mismatches.
- Supported Blender: 4.5.x LTS (primary, 4.5.12 at time of writing), 4.2.x LTS (tolerated). The
  `probe` job reports version; the runner warns on 4.3/4.4 and refuses ≥ 5.0 unless
  `blender.allow_unsupported = true` (see `18_…` R-07). Note: Homebrew's `blender` and `blender@lts`
  casks ship 5.x; 4.5 LTS must be installed from blender.org or a mirror.
- Supported Unity: 6000.x URP. The C# package declares `"unity": "6000.0"`.
